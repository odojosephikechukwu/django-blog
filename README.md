# Django blog

A Django 6 blog (`mysite`) with one app, `blog`. Public pages live under `/blog/`. The admin is `/admin/`.

The app includes posts, comments, tags (`django-taggit`), PostgreSQL full-text search, an RSS feed, a sitemap, and email sharing.

Search uses `SearchVector`, and `django.contrib.postgres` is in `INSTALLED_APPS`. The commented-out SQLite settings and the `db.sqlite3` file in the project root will not run this app. You need PostgreSQL.

## Ports already in use on this machine

| Port | What is using it |
|---|---|
| `8000` | A PHP app. Do not use this port. |
| `5432` | The `aeluvista-postgres` Docker container. That is a different application's database. |

Run this blog on port **8002**, and give it a Postgres container on port **5433**.

## 1. Python environment

From the project root:

```bash
cd /home/tfnbackend/Projects/Dev/joenwa/django-blog
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install "Django>=6,<6.1" django-taggit "psycopg[binary]"
```

Migrations in this repo were generated by Django 6.0, and posts use `django-taggit`, so both of those packages are required. There is no `requirements.txt`.

## 2. Database

`mysite/settings.py` expects a database named `mysite_db`, a user named `mysite_user`, host `localhost`, and port `5432`. Point `PORT` at the new container instead of the existing one:

```python
'PORT': '5433',
```

Leave `NAME`, `USER`, and `PASSWORD` as they already are in that file. Then start Postgres with those same three values:

```bash
docker run -d --name mysite-postgres \
  -e POSTGRES_DB=mysite_db \
  -e POSTGRES_USER=mysite_user \
  -e POSTGRES_PASSWORD='<PASSWORD from mysite/settings.py>' \
  -p 5433:5432 \
  postgres:16-alpine
```

Apply the migrations and create an admin user:

```bash
source .venv/bin/activate
python manage.py migrate
python manage.py createsuperuser
```

`migrate` creates the blog tables, comments, tags, and the `django.contrib.sites` row (`SITE_ID = 1`).

## 3. Start the site

```bash
python manage.py runserver 127.0.0.1:8002
```

Open:

- http://127.0.0.1:8002/blog/ — post list (empty until you publish something)
- http://127.0.0.1:8002/admin/ — create a post, set **Status** to **Published**, add tags, and save
- http://127.0.0.1:8002/blog/search/?query=your+word — full-text search
- http://127.0.0.1:8002/blog/feed/ — RSS
- http://127.0.0.1:8002/sitemap.xml — sitemap

A published post is available at `/blog/YYYY/MM/DD/slug/`. Drafts stay out of the public list.

## Email sharing

The "share by email" form sends through Gmail SMTP using the address and app password in `mysite/settings.py`. That password is in the repo. Rotate it in the Google account, then move the email values and the database password into environment variables before sharing this project or deploying it.
